Update the MelaBridge vendor experience to match the actual business model.

IMPORTANT:
MelaBridge is NOT an internal vendor messaging platform and is NOT a vendor booking CRM.

Personal users should use MelaBridge primarily to DISCOVER vendors, VIEW vendor profiles, SAVE/FAVORITE vendors, and then CONTACT vendors directly outside of MelaBridge.

Do not build functionality that implies MelaBridge knows what happens after a user contacts a vendor externally.

==================================================
1. REMOVE "BOOKINGS" FROM PERSONAL ACCOUNTS
==================================================

The Personal account currently shows "Bookings" in navigation and a "Vendor bookings" page.

Remove this from PERSONAL accounts.

Personal users should NOT see:
- Bookings
- Vendor Bookings
- Booking Pipeline
- Contacted status
- Availability status
- Quote Sent status
- Quote Received status
- Waiting for Response
- Hired status
- Any manually selected vendor relationship statuses

Do not simply rename the existing booking pipeline.

Remove the unnecessary workflow from the Personal experience.

==================================================
2. MAKE "VENDORS" THE DISCOVERY CENTER
==================================================

The existing Vendors section should become the central place for Personal users to discover and save vendors.

Personal users should be able to:

- Browse vendors
- Search vendors
- Filter vendors
- View vendor profiles
- Favorite vendors
- Unfavorite vendors
- View all saved/favorite vendors
- View vendor contact information
- Contact vendors outside MelaBridge

If useful, create tabs inside Vendors such as:

Discover
Favorites

Do NOT create another unnecessary sidebar item if Favorites can be handled cleanly inside Vendors.

==================================================
3. FAVORITES MUST BE A REAL FEATURE
==================================================

Add a clear heart/favorite control to:

- Vendor discovery cards
- Vendor profile pages

When a user favorites a vendor:

- Save it to the authenticated user's account/database
- Immediately update the UI
- Keep the favorite after logout/login
- Allow the user to unfavorite
- Show favorited vendors under Favorites
- Prevent duplicate favorite records

Do not implement favorites using temporary browser/local state only.

If appropriate, allow a user to associate a favorite vendor with one of their events for organization, but do not turn this into a booking workflow.

==================================================

- Cover/portfolio image
- Business name
- Vendor category

- Favorite heart
- View Profile

Keep cards visually clean and responsive.

Do not display booking statuses or relationship pipelines.

- Services

- Phone number
- Email

Contact information should be easy to find.

==================================================
6. CONTACTING A VENDOR
==================================================

MelaBridge users will contact vendors OUTSIDE of MelaBridge.

Provide external contact actions based on information supplied by the vendor.

Examples:

Call
Email
Visit Website
Instagram
Other supported social links

"Contact Vendor" must NOT open an internal MelaBridge chat unless an actual messaging platform is intentionally built in the future.

Do not create fake communication tracking.

MelaBridge cannot reliably know whether:

- A vendor responded
- Availability was confirmed
- A quote was sent
- A quote was accepted
- The vendor was hired
- A conversation occurred

Therefore, do not automatically or manually display those statuses.
